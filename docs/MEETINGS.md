# 회의록 · 기능 추적 — 기획안

회사 내부 회의록을 정리하고, 회의에서 나온 결정을 **서비스·앱 단위 기능**으로 등록해 배포까지 추적한다.
보는 사람은 **직원만**이다. 회의록에는 외부에 나가면 안 되는 내용이 담기므로 다른 화면보다 보안 기준을 높게 둔다.

> 상태: **3단계 완료** (2026-11-20). 0단계 일부(토큰·git 이력·운영 .env)는 직접 처리 필요. 남은 것은 4단계(선택 사항).

## 2. 위협과 대책

| 위협 | 대책 |
|---|---|
| 권한 없는 직원이 열람 (지금은 viewer 도 모든 화면을 봄) | 역할(viewer/operator/admin)과 별개인 **회의록 권한** `users.meeting_access`. 회의마다 공개 범위 |
| 비밀번호 유출 | 회의록 권한이 있으면 **TOTP 2단계 인증 필수**. 등록 전에는 회의록 화면 진입 불가 |
| DB 파일·백업·설정 스냅샷 유출 | 본문·결정 사항을 **앱 키로 암호화**해 저장. 키는 `.env` 에만 두고 DB·백업·git 에 넣지 않음 |
| 누가 봤는지 모름 | **감사 로그**: 열람·작성·수정·삭제·공개 범위 변경·권한 변경을 사용자·IP·시각과 함께 기록. 화면에서 수정·삭제 불가 |
| 설정 스냅샷(`database/config.sql`)에 섞여 git 으로 나감 | `ConfigSnapshot::TABLES` 에 회의 관련 테이블을 넣지 않고, 테스트로 고정 |
| 문자 알림으로 내용 노출 | 알림에는 제목·링크만. 본문·결정 사항은 넣지 않음 |
| 마크다운 본문 XSS | 원본 HTML 은 이스케이프, 링크는 `http(s)`·`mailto` 만 허용 |
| 자리 비운 사이 열람 | 회의록 화면은 유휴 15분이면 재인증 (`MEETING_IDLE_MINUTES`). 공개 범위 변경·내보내기 전 비밀번호 재확인 |
| 브라우저·프록시 캐시 | 회의록 응답에 `Cache-Control: no-store` |
| 검색 엔진·외부 노출 | 기존 IP 허용 목록(`ALLOWED_IPS`) 그대로 적용. 운영은 HTTPS + `SESSION_SECURE_COOKIE=true` 필수 |

## 4. 데이터 구조

```
users ─ meeting_access, totp_*
  │
meetings ─ N:M ─ users (참석자, meeting_attendees)
  │  └─ 0..1 ─ systems (관련 서비스, 선택)
  │ 1:N
features ─ N:1 ─ systems / apps
  │ 1:N
feature_events (상태 변경 이력)

audit_logs (회의록·기능·권한 관련 모든 행위)
```

### `users` 추가 컬럼

| 컬럼 | 내용 |
|---|---|
| `meeting_access` | 회의록 권한 `none` / `read` / `write`. 기본 `none` |
| `totp_secret` | TOTP 비밀값 (**앱 키로 암호화**해 저장) |
| `totp_enabled_at` | 2단계 인증 등록 시각. NULL 이면 미등록 |
| `totp_last_step` | 마지막으로 통과한 시간 단계 (같은 코드 재사용 방지) |

- 모두 `ConfigSnapshot` 에서 제외
- 복구 코드는 1단계에서는 두지 않고, 분실 시 관리자가 2단계 인증 초기화 (감사 로그에 기록)

### `meetings` (회의록)

| 컬럼 | 내용 |
|---|---|
| `title` | 제목 (평문. 목록·검색용이므로 민감한 내용은 쓰지 않도록 안내) |
| `held_at` | 회의 일시 |
| `system_id` | 관련 서비스 (선택) |
| `visibility` | `all` (회의록 권한자 전체) / `attendees` (참석자·작성자만) / `private` (작성자만) |
| `body_enc` | 본문 마크다운, **암호화** |
| `decisions_enc` | 결정 사항, **암호화** |
| `author_user_id` | 작성자 |
| `deleted_at` | 휴지통 (NULL 이 아니면 목록에서 숨김) |
| `created_at`, `updated_at` | |

### `meeting_attendees`

| 컬럼 | 내용 |
|---|---|
| `meeting_id`, `user_id` | 참석자 (직원 계정). 외부 참석자는 본문에 적음 |

### `features` (기능)

| 컬럼 | 내용 |
|---|---|
| `system_id` | 서비스 (필수) |
| `app_id` | 앱 (선택. 앱 단위 기능일 때) |
| `title` | 기능 이름 |
| `description` | 설명 (평문. 기능 추적은 기존 역할 체계를 따름) |
| `status` | `requested` 요청 → `planned` 확정 → `in_progress` 개발 → `released` 배포됨 / `on_hold` 보류 / `dropped` 취소 |
| `target_version` | 목표 버전 (예: 1.4.0) |
| `released_version`, `released_at` | 실제 배포 버전·일시 |
| `meeting_id` | 출처 회의 (선택) |
| `incident_id` | 관련 장애 (선택) |
| `assignee_user_id` | 담당자 (선택) |

- 삭제하지 않고 `dropped` 로 둔다 (장애·리소스와 같은 원칙)
- 출처 회의 링크는 **그 회의를 볼 수 있는 사람에게만** 표시. 못 보는 사람에게는 "회의에서 등록됨" 만 표시

### `feature_events`

장애 타임라인(`incident_events`)과 같은 방식. 상태 변경, 목표 버전 변경, 메모를 사용자·시각과 함께 남긴다.

| 컬럼 | 내용 |

| `target_type`, `target_id` | 대상 |
| `ip`, `user_agent` | |
| `detail` | 변경 요약 JSON (본문 내용은 넣지 않음) |
| `created_at` | |

- 앱에는 INSERT 만 있고 UPDATE·DELETE 경로 없음
- 보관 기간: 1년 (cron 이 정리). 정리 자체도 기록

## 5. 암호화

- **방식**: libsodium `sodium_crypto_secretbox` (PHP 기본 내장, 추가 패키지 불필요). 값마다 무작위 nonce, 저장 형식 `v1:` + base64(nonce + 암호문)
- **키**: `.env` 의 `APP_KEY` (32바이트, base64). 생성: `php -r 'echo base64_encode(random_bytes(32));'`
  - 키가 없으면 회의록 화면을 열지 않고 오류 안내 (평문 저장으로 넘어가지 않음)
  - 키는 DB 백업과 **다른 곳**에 따로 보관 (예: 비밀번호 관리자). 키를 잃으면 회의록 복구 불가
- **키 교체**: `APP_KEY_PREVIOUS` 를 두고 `composer meetings:rekey` 로 전체 재암호화. 버전 접두사(`v1:`)로 구분
- **검색**: 본문은 DB 에서 검색할 수 없다. 1단계 검색은 제목·기간·서비스·참석자·작성자만
  - 나중에 필요하면 권한 있는 사용자가 검색할 때 대상 회의를 복호화해 메모리에서 찾는다 (수백 건 규모까지)
- **암호화하지 않는 것**: 제목, 일시, 참석자, 서비스 연결. 목록·필터에 필요하므로 평문. 제목에 민감 내용을 쓰지 않도록 입력란에 안내

## 7. 2단계 인증 (TOTP)

- 표준 TOTP (RFC 6238, 30초, 6자리). Google Authenticator, 1Password 등 사용 가능
- 구현은 직접 (HMAC-SHA1 + base32, 수십 줄). QR 코드는 외부 서비스에 비밀값을 보내지 않도록 서버에서 SVG 로 생성 (작은 라이브러리 1개 추가 또는 직접 구현)
- 흐름: 로그인 → 회의록 화면 진입 시 2단계 인증 미등록이면 `/profile/2fa` 등록 화면 → 등록 후 코드 입력 → 세션에 통과 시각 기록
- 회의록 화면은 통과 후 `MEETING_IDLE_MINUTES`(기본 15분) 동안 활동이 없으면 코드 재입력
- 실패 5회면 15분 잠금 (기존 `login_attempts` 와 같은 방식), 실패는 감사 로그 `auth.totp_fail`
- 앞뒤 1단계(±30초) 허용, `totp_last_step` 으로 같은 코드 재사용 차단
